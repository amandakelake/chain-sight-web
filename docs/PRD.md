# 产品需求文档：ChainSight Web 前端壳层

---

## 1. 项目定位

### 1.1 背景

ChainSight AI 后端已经具备清晰的事件监控与 AI 洞察规划，但前端仍处于模板阶段。Web 端需要提供一个稳定、可扩展的壳层，承载未来的监控工作台、AI 解读和通知管理能力，并为多终端协同打下体验基础。

### 1.2 产品愿景

构建一个“链上情报驾驶舱”，让不同角色在浏览器内即可完成订阅配置、事件回溯、AI 报告消费与协作。前端需做到信息有序、操作可控、响应及时，并能根据后端的功能演进逐步开关模块。

### 1.3 目标用户

| 角色          | 核心诉求                           | 第一阶段价值                       |
| ------------- | ---------------------------------- | ---------------------------------- |
| 交易员/研究员 | 快速感知高价值事件，查看历史上下文 | 统一的 Dashboard 视图与事件列表    |
| 基金/风控团队 | 关注持仓风险、团队协作             | 多订阅管理、团队共享视角（规划中） |
| 新手投资者    | 低门槛了解事件含义                 | AI 解读卡片与引导式流程            |

### 1.4 成功指标

- **激活度**：首周登陆 2 次以上的用户数。
- **转化链路**：完成“创建订阅”引导的比例 ≥ 60%。
- **交互效率**：核心操作（创建/编辑/暂停订阅）平均 3 步内完成。
- **稳定性**：前端重要交互（订阅配置、通知查看）错误率 < 0.1%。

## 2. 用户旅程与信息架构

| 阶段       | 触点                  | 主要界面                                    | 备注                                                     |
| ---------- | --------------------- | ------------------------------------------- | -------------------------------------------------------- |
| 发现       | 公共营销页面 / 登录页 | `/landing`（规划）                          | 提供产品价值与 CTA                                       |
| 建立信任   | 入门引导              | `/dashboard/default` 首次引导层             | 展示产品骨架、关键指标容器                               |
| 配置监控   | 订阅配置向导          | `/dashboard/subscriptions`                  | 多步骤流程：目标地址 → 事件类型 → AI 解释偏好 → 通知渠道 |
| 消费信息   | 通知与洞察            | `/dashboard/streams`、`/dashboard/insights` | 卡片化时间线 + AI 说明                                   |
| 回顾与协作 | 报告中心              | `/dashboard/reports`                        | 分享、导出、备注（后续版本）                             |

## 3. 页面与功能里程碑

### Phase 0（当前迭代）：前端壳层

- 统一的布局（侧边栏 + 顶部信息条）。
- 体验占位：概览卡片、流程引导、开发进度说明。
- 技术基线：主题、字体、响应式栅格、API 适配层。

### Phase 1：监控工作台 MVP

- **订阅列表**：支持创建、激活/暂停、查看最近事件。
- **事件时间线**：展示链上事件的核心字段与跳转链接。
- **渠道状态**：Telegram/Discord 绑定状态提醒。

### Phase 2：AI 解读与洞察

- **AI 摘要卡片**：在事件卡片旁展示自然语言解释。
- **地址标签展示**：高亮“聪明钱”“交易所”等标签。
- **意图猜测**：以标签或徽章形式呈现系统判断。

### Phase 3：模式分析与报告

- **聪明钱雷达**：自定义视图 + 高亮提醒。
- **异常监测看板**：趋势图 + 阈值标注。
- **报告中心**：历史分析、导出、收藏。

## 4. 导航与布局方案对比

| 方案                     | 描述                                     | 优点                             | 风险/成本                    | 适用性                                |
| ------------------------ | ---------------------------------------- | -------------------------------- | ---------------------------- | ------------------------------------- |
| A. 侧边栏 + 顶栏（推荐） | 保留固定侧边导航，顶部放置全局状态与 CTA | 扩展性强、符合数据密集型产品习惯 | 占用横向空间，需要在小屏优化 | 满足多模块、未来可折叠                |
| B. 单列 Tab 栏           | 使用顶部 Tab 切换主要模块，辅以面包屑    | 移动端适配简单，视觉轻           | 模块增多时易拥挤，缺少上下文 | 仅适用于 2-3 个核心模块，后续扩展受限 |

当前版本采用方案 A，并在 1024px 以下自动收起侧边栏，以兼顾可读性与扩展性。

## 5. 页面结构 & 状态规划

### 5.1 Dashboard 总览

- 顶部“今日状态”条：展示数据同步状态、通知渠道状态、系统公告。
- 主体三列布局：
  1. **概览卡片**：订阅数、监控目标、告警数。
  2. **事件占位**：时间线 + 空状态文案（引导创建订阅）。
  3. **AI 实验区**：预留交互区，展示未来的 Agent 功能预告。

### 5.2 Subscriptions 模块

- 列表：名称、链、状态、最近事件时间。
- 操作：创建、复制、停用，全部在行内完成。
- 引导：首次访问弹出“3 步创建”浮层。

### 5.3 Streams/Insights 模块

- 左侧事件流，右侧 AI 解读。
- 支持按事件类型、地址标签筛选；支持“仅看高优先级”。

## 6. 数据交互与接口契约

| 模块     | 所需 API                            | 关键字段                                       | 备注                   |
| -------- | ----------------------------------- | ---------------------------------------------- | ---------------------- |
| 订阅列表 | `/api/subscriptions` GET/POST/PATCH | id、address、chainId、events、status、channels | 对接后端 F-002/F-003   |
| 事件流   | `/api/events` GET                   | txHash、eventType、value、labels、interpretion | 需支持分页与按订阅过滤 |
| AI 解读  | `/api/events/{id}/insight` GET      | summary、intentTag、confidence                 | 对接后端 F-005/F-007   |
| 配置偏好 | `/api/user/preferences`             | theme、layout、notificationMode                | 可缓存于 localStorage  |

前端需提供统一的 API 客户端，封装身份凭证、错误兜底与重试策略。

---

## 7. 技术与实现约束

- **技术栈**：Next.js 16 App Router、TypeScript、Tailwind 4、shadcn/ui。
- **状态管理**：轻量场景使用 React 组件状态 + `useQuery`；订阅流程使用 Zustand（或 React Server Actions 后续替换）。
- **主题系统**：延续 Vercel 官方模板的 CSS 变量方案，命名统一抽象（`--cs-semantic-bg` 等）。
- **可测试性**：关键流程至少提供 Playwright/RTL 的冒烟测试用例（在功能落地时补齐）。

---

## 8. 非功能与体验原则

- **性能**：骨架渲染时间 < 1s，首屏请求数控制在 6 个以内。
- **可访问性**：全部交互控件支持键盘导航与 ARIA 标签。
- **可观察性**：接入前端埋点（国家/浏览器、关键操作耗时）。
- **国际化准备**：文案集中管理，默认中文，预留英文资源文件。

---

## 9. 范围之外（当前迭代）

- 可视化报表（折线、热力）仅保留占位，不实现数据绘制。
- 协作/评论系统暂不实现，仅规划入口。
- 移动端独立体验暂不上线，仅保证响应式可正常浏览。
- 钱包直接交易、资产托管等功能均不在 Web 前端范围内。

---

## 10. 下一步建议

1. 将后端 PRD 的 Phase 1 接口转化为 OpenAPI，便于前端生成类型。
2. 在 `src/data` 中维护 mock 数据（订阅、事件）以解耦早期开发。
3. 先落地订阅流程的空状态与引导，再逐渐填充真实数据，保证体验一致。
